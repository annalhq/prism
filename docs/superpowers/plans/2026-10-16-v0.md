# Usable Prism v0 Implementation Plan

> For agentic workers: use executing-plans for integration and dispatching-parallel-agents for the independent modules below. User authorizes baseline implementation now and defers broad testing/improvement until later.

**Goal:** A usable browser workspace over the implemented private vault, with saving, notes, organization, people and confirmed field/interest personas, local persistence, basic sync/search and portable data access.
**Architecture:** Preserve existing command/receipt transaction. Add bounded bootstrap/change reads and a durable local facade; UI consumes that facade. Profile membership and relationships remain explicit. No provider migration or live infrastructure writes.
**Spec:** ARCHITECTURE.md and plan.md, with user's explicit v0-first priority and persona confirmation in this conversation.

## Global constraints

One configured owner. No leaked private env. Requests/frames/pages <=1 MiB, bulk <=100. Notes <=100 KiB. Preserve pending envelopes/drafts through failures; retry identical operations; no silent note overwrite. Notes create backlinks only. Persona means named field/interest context, explicitly confirmed. Clipper research remains deferred. No broad browser/database/performance suite now; run check/lint/build and focused local checks.

## Parallel interfaces

`src/lib/domain/replica.ts` (sync implementer owns):

- `ReplicaTable`: entities/bookmarks/people/personas/notes/tags/collections/links/identities/relationships/memberships/savedSearches/activity.
- `ReplicaRecord = { table: ReplicaTable; key: string; lastSeq: Sequence; value: Record<string, unknown> }`.
- Bootstrap start `{ token, epoch, startSeq, cursor, tables, expiresAt }`.
- POST `/api/v1/sync/bootstrap`; GET `/api/v1/sync/bootstrap/:token?table=...&after=...` -> `{records,nextAfter}`; DELETE token releases lease.
- GET `/api/v1/sync/changes?cursor=...` -> `{frames,cursor,hasMore,epoch}`.
- Records use existing domain projections. links is full `{sourceId,lastSeq,edges}` per source, key sourceId. Relationships key bookmarkId/personId/role. Memberships key personaId/memberId. Others use id/entityId/bookmarkId.

`src/lib/client/vault/library.ts` (local implementer owns):

- `createLibraryClient(notify: () => void)` exposes `state`, `start`, `stop`, `sync`, `list<T>(table): T[]`, `get<T>(table,key): T|undefined`, `save(command): Promise<{status:'accepted'|'queued'|'rejected'|'already_exists';message?:string;existingId?:string}>`, `getDraft(id): {body:string;baseRevision:Revision}|undefined`, `setDraft(id,body,baseRevision)`, `clearDraft(id)`, `exportPending()`.
- State `{ready,loading,online,status,error,pending,conflicts,identity}`; conflicts include envelope/error/current remote; never discard drafts/pending. Scope storage by deployment and owner vault. Bootstrap stages records and replays from H before swapping; cursor moves only on pull. Store full revisioned projections with lastSeq.

Persona implementer owns new domain/personas.ts and server/vault/personas.ts and cleanup file if needed:

- Exports `PersonaCommand`, `PersonaChange`, `PersonaProjection`, `PersonaMemberProjection`, `parsePersonaCommand`, `isPersonaCommand`, `applyPersonaCommand(tx,vaultId,command,seq,now)`.
- Root integrates unions/dispatch/projection helper. Create/update/trash/restore/purge and membership.add/remove; no nesting, no implicit inherited membership. Persona member wire `{personaId,member:{kind,id},revision,lastSeq,deletedAt,createdAt,updatedAt}`.
