# Prism v0

The root page now provides the library workspace. This is an implementation baseline for trying the workflow; the original release gates and broader functional testing remain open.

## Try it

Run `bun run dev`, open the URL Vite prints (normally `http://localhost:5173`), and sign in with the configured owner account. Use the origin registered with Neon Auth and configured in `APP_ORIGIN`. Restart an already running development server after pulling these dependency changes.

The existing Task 2 database and owner setup are required for saving and synchronization. This slice adds no schema migration. See [Task 2 setup](task-2.md) and the [README](../README.md) for authentication configuration. An unconfigured server renders the welcome workspace but cannot load a private library.

Start with **New** to save a page, social post, image reference, person or persona. Select an item to edit metadata, notes and connections. Use the sidebar for organization and the header menu for import/export and cleanup. On a narrow screen, the inspector replaces the list; Back returns to the list.

## Available baseline

- Saved content: capture, duplicate-URL feedback, metadata editing, reading status, pin, archive, trash/restore and explicit permanent deletion. Image references do not upload image bytes.
- Notes: local drafts, explicit save, safe Markdown preview, typed internal references, backlinks, related links and previous revisions. Draft rebasing is explicit when the server note changes.
- Organization: tags, collections, saved searches and bulk content operations in bounded chunks.
- People: distinct profiles, confirmed identities, explicit authored/about/related roles and profile feeds.
- Personas: named knowledge contexts such as “Systems Engineering,” with notes, tags and explicit person/content memberships. Adding a person does not automatically add their content; the derived authored-content view is labeled separately. Personas cannot nest.
- Retrieval: local worker queries, phrases and filters such as `#tag`, `@collection`, `person:"Name"`, `author:"Name"`, `persona:"Name"`, `site:example.com`, `has:note` and `status:unread`. Invalid or ambiguous filters show errors.
- Local work: owner-scoped IndexedDB replica, durable command outbox and drafts, bounded bootstrap/change pulls, reconnect and visible-tab polling, and visible sync/conflict states. Conflicted commands require review; pending work can be exported.
- Offline shell: service worker caches static assets and the public shell. After a successful visit, **Open cached library on this trusted device** permits explicit offline access. Private API/auth responses are excluded from shell caching.
- Portability: confirmed metadata export, separate pending-work/draft export, copy-import preview and downloadable results. Imports use fresh IDs, preserve existing URL duplicates, and retain unresolved note bodies in the report for review.
- Maintenance: an owner-only, manually invoked bounded profile-cleanup endpoint, exposed in library settings.

## Limits and remaining work

Use a browser supporting IndexedDB, workers and Web Locks over HTTPS or localhost. Automatic sync deliberately pauses without Web Locks to protect concurrent tabs; queued work and drafts remain available. Cached content is for trusted devices and is not end-to-end encrypted. Signing out does not erase IndexedDB; browser site-data removal clears local copies, including any unexported pending work.

Search currently sends a local projection snapshot to the worker per query; indexing, large-library performance and measured budgets remain unfinished. Polling provides baseline synchronization; multi-device, crash/reload, lease-expiry and lost-response behavior still need functional verification. Offline reload and mobile/keyboard behavior also need browser testing.

Import is a sequence of commands, not one atomic restore. It stops on uncertain or rejected saves and has no persistent import-job resume. Download the report, especially when notes require review. Metadata export excludes media bytes and is not a full disaster-recovery backup.

Still pending: B2 upload/download/verification and media cleanup (Task 13), full backups/migrations/restore drill (Task 15), scheduled maintenance and operational visibility (remaining Task 16), extension/enrichment (17–18), and quality/performance gates (9/19). Clipper design (22) remains deferred. The `maintenance` CLI is still a placeholder; the implemented manual API handles person/persona cleanup only.

## Verification

Basic Svelte/TypeScript, lint and production build checks are recorded for this slice. A credential-free production HTTP smoke check returned the workspace with status 200 and an unconfigured session response with `no-store`. Focused local checks covered replica sequence/purge rules, cursor scope/bigint handling and import reference/duplicate handling.

No live database writes, migrations, B2 calls or broad browser/database/performance suites were run for this slice. Chromium is not installed in this environment. These checks establish a buildable baseline, not validated multi-device correctness or release readiness.
